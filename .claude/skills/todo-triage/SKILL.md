이 세션의 결과물은 `docs/STATUS.md`에 넣을 항목이다. 코드는 바꾸지 않는다. 해결 방법은 구현 세션의 몫이다. 확인 중에 알아낸 원인은 확인 근거에 한 줄로 남기고, 원인을 찾으려 따로 조사하지 않는다.

오타나 깨진 링크처럼 바로 고칠 수 있는 작은 문제는 항목으로 만들지 않는다. 사용자에게 바로 고치라고 지시할 수 있다고 한 줄로 알린다.

지적마다 아래 순서로 진행한다.

1. 실제로 있는지 확인한다. 화면과 동작 문제는 실행해서 재현하고, 재현할 수 없을 때만 코드로 확인한다. 기능 요청이면 이미 있는 기능인지 확인한다. 재현은 로컬 DB에서 하고 운영 데이터는 바꾸지 않는다.
2. 같은 유형이 다른 곳에도 있는지 확인한다.
3. 결과에 맞는 위치를 고른다.
   - 재현 또는 코드로 확인됨: 다음 할 일
   - 확인 불가: 아직 검증 못 한 것 (시도한 방법과 막힌 이유를 함께 적는다)
   - 존재하지 않음: 기록하지 않고 사용자에게 근거를 알린다
4. 마피아MCP로 항목에 빠진 관점을 점검한다. 카드 내용은 옮기지 않고, 프로젝트 사실만 우리 말로 쓴다.
5. 아래 양식으로 항목을 쓴다.

```markdown
### 항목 제목
- 유형: 문제 | 기능
- 현상/요구: 사용자 시각에서 무슨 일이 일어나는지, 또는 무엇이 필요한지
- 확인 근거: 재현 경로 또는 코드 위치, 확인 수준, 확인 커밋(YYYY-MM-DD). 알아낸 원인이 있으면 한 줄 추가
- 영향 범위: 같은 유형이 있는 곳
- 완료 기준: 어떤 동작이 되면 끝인지
- 제약: 이번에 하지 않을 것
```

세션의 첫 항목은 바로 보여 주고 양식과 상세 수준을 맞춘다. 나머지는 세션 끝에 넣을 문장을 그대로 모아 보여 주고, 승인받은 뒤 반영한다.
